# QA 验收清单

本文档用于发布前人工验收静态站，自动校验脚本只负责结构与内容完整性，最终仍需浏览器确认。

## 自动校验

在仓库根目录运行：

```bash
npm run validate
```

发布前必须看到 `Result: PASS`。脚本会检查：

- `index.html` 可找到。
- 固定套路关键字齐全：七字段、钱/关系/技能/影响力、道/法/术/器。
- 可从 `data/cases.json`、内联脚本或本地脚本识别 24 个 case。
- 每个 case 有 7 个抽取字段、4 个 value score、4 个 pillar。
- 页面包含隐藏连接、行动清单、小伟视角、微信引流位。
- 可见页面文案和 case 数据没有明显 `TODO`、`undefined`、`null` 泄漏。

最近一次记录：

```text
时间：2026-05-05
命令：npm run validate
结果：PASS，13 checks
数据来源：data/cases.json
```

## 桌面端验收

建议用 Chrome 或 Safari 打开本地 `index.html`，宽度优先检查 1440px 和 1280px。

- 首屏能看到标题、固定套路说明、CTA 和右侧套路面板，导航吸顶不遮挡正文。
- 统计区、隐藏连接、行动清单、小伟视角、24 份拆解、微信引流位都能顺序滚动到。
- case 卡片中价值评分、七字段抽取、道法术器、行动清单、小伟视角不重叠、不截断。
- 搜索栏和筛选栏吸顶时不挡住 case 标题。
- 页面没有明显空白断层、横向滚动条、图片或字体加载导致的布局跳动。

## 移动端验收

用浏览器设备模拟或真机检查 390px、430px 左右宽度。

- 顶部导航可横向滚动，微信入口不挤压品牌区。
- 首屏标题、说明和按钮不溢出，下一段内容有自然露出。
- case 卡片改为单列后，评分、七字段、道法术器按顺序展示。
- 搜索框、筛选按钮、空状态文案在小屏不遮挡、不被吸顶栏盖住。
- 微信引流位在小屏下微信号区域可读，长微信号也应换行。

## 筛选与搜索

本地和线上都需要抽查。

- 点击 `全部`，数量应为 24。
- 依次点击 `AI编程出海`、`PPT设计变现`、`教育改造` 等主题，数量和卡片主题一致。
- 搜索 `孟建`，应出现孟建相关 case。
- 搜索 `PPT`，应出现 PPT 设计变现相关 case。
- 搜索 `AI App`，应出现 AI App 增长相关 case。
- 搜索一个不存在的词，应出现空状态“没有匹配结果，换个关键词试试。”。
- 清空搜索后，筛选和列表恢复正常。

## GitHub Pages 在线确认

发布后打开 GitHub Pages URL，进行硬刷新再验收。

- 页面不是 GitHub Pages 404，也不是旧版本缓存。
- `<title>`、首屏标题、24 份 case、微信引流位与本地一致。
- 浏览器控制台没有红色运行时报错。
- Network 面板没有阻断页面渲染的 404 资源；如果未来拆出 `data/cases.json`，必须确认该文件返回 200。
- 在线页面也运行一次核心搜索和主题筛选抽查。

## 微信号替换检查

当前页面已配置真实微信号；后续换号时必须保持所有入口一致。

- 全局搜索旧占位文案，正式发布版本应为 0 处。
- 顶部按钮、底部微信引流位、正文说明里的微信号必须一致。
- 替换后重新检查移动端长文本换行，不能撑出横向滚动。
- 替换后重新运行 `node scripts/validate-site.mjs`，并在线确认新版本已生效。
