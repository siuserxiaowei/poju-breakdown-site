# 前端视觉系统

## 设计方向

当前站点定位为“大会作战档案 / 术语道手册”，不是营销落地页。视觉目标是让用户快速扫描 24 份内容，并清楚看到每篇稿件的固定拆解套路。

## 视觉原则

- 背景采用深色档案台面，内容卡采用纸张色，形成“夜间翻档案”的阅读感。
- 主强调色使用红色，辅助使用绿色、金色、蓝色，避免单一色调。
- 卡片半径控制在 8px 以内，保持资料站的硬朗感。
- 首屏强调“道法术器拆解档案”，但真正内容第一屏可继续下探，不做空洞大 hero。
- 内容卡密度较高，优先扫描效率：编号、来源、主题、评分、七字段、道法术器分区固定。

## 组件

- `topbar`：固定导航，包含固定套路、隐藏连接、行动清单、案例拆解、微信入口。
- `hero`：解释固定套路，右侧为 method pipeline。
- `stats`：展示来源数、七字段、四维评分、道法术器。
- `connections`：跨内容隐藏连接。
- `action-grid`：今天、本周、本月行动清单。
- `toolbar`：搜索和主题筛选。
- `case`：核心内容卡，包含价值评分、七字段、道法术器、行动清单、业务转译。
- `lead`：微信引流位。

## 交互

`assets/site.js` 负责从 `window.POJU_SITE_DATA` 渲染页面：

- 渲染 meta、统计、pipeline、隐藏连接、全局行动清单。
- 渲染 24 个 case。
- 支持按主题筛选。
- 支持全文搜索，搜索范围覆盖标题、来源、字段、工具、金句、道法术器和行动清单。
- 支持 reveal 动效，浏览器不支持 `IntersectionObserver` 时仍然正常展示。

## 移动端策略

- 复杂网格在窄屏下改为单列。
- 筛选器允许横向滚动，避免按钮挤压变形。
- 卡片内部七字段、评分、道法术器均降级为单列或双列，保证中文长句不溢出。

## 接入方式

构建脚本会把：

- `assets/site.css`
- `assets/site.js`
- `data/site-meta.json`
- `data/cases.json`
- `src/index.template.html`

合成为根目录 `index.html`，用于 GitHub Pages 静态部署。
