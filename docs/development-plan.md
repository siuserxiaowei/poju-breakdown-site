# 破局拆解站开发计划

## 目标

把当前单文件展示页升级成可持续复用的“术语道 / 道法术器”资料站：后续新增 Markdown 后，可以先结构化成数据，再生成同一套网页，而不是每次手工改 HTML。

## 固定内容套路

每份稿件都必须经过同一条链路：

1. 从逐字稿抽取：嘉宾身份、真实结果、关键数据、核心故事、方法框架、工具清单、金句。
2. 判断值不值得学：钱、关系、技能、影响力四维评分，区分短期和长期价值。
3. 进入道法术器：道是底层认知，法是可迁移方法，术是具体打法，器是工具和资源。
4. 提炼跨内容隐藏连接：串出不同嘉宾之间的共性和大会主线。
5. 给行动清单：今天、本周、本月分别能做什么。
6. 加业务转译：把内容翻译成作者自己的业务动作。

## 并行开发线

### 内容数据层

产物：

- `data/cases.json`
- `data/site-meta.json`
- `docs/content-audit.md`

验收：

- 24 个 Markdown 都有对应 case。
- 每个 case 都有 7 个抽取字段、4 组价值评分、4 个道法术器字段。
- 信息不足处要明确标注为基于标题或正文的归纳。

### 前端体验层

产物：

- `assets/site.css`
- `assets/site.js`
- `docs/frontend-system.md`

验收：

- 桌面和移动端都能扫描阅读。
- 视觉方向统一为大会档案 / 作战手册。
- 搜索、筛选、返回顶部和基础交互可用。

### 生成流水线

产物：

- `scripts/build-site.mjs`
- `src/index.template.html`
- `package.json`
- `docs/pipeline.md`

验收：

- `npm run build` 能从 data、assets、template 生成 `index.html`。
- 生成结果适配 GitHub Pages 静态部署。
- 无外部服务依赖。

### 验收发布层

产物：

- `scripts/validate-site.mjs`
- `docs/qa-checklist.md`

验收：

- 能检查固定套路关键字段、case 数量、道法术器结构、行动清单、业务转译、微信引流位。
- 能兼容当前单文件和未来生成式站点。

## 主线整合策略

1. 先回收数据层，确认内容结构能覆盖 24 份稿件。
2. 再回收流水线层，让 `index.html` 从数据和模板生成。
3. 接入前端层的样式和交互。
4. 最后接入 QA 层，建立本地验证和线上验证流程。
5. 验收通过后推送 `main`，触发 GitHub Pages 发布。

## 发布验收

每次发布前必须跑：

```sh
npm run build
npm run validate
```

每次发布后必须确认：

- GitHub Pages 返回 HTTP 200。
- 页面包含“道法术器拆解档案”。
- 页面包含“钱 / 关系 / 技能 / 影响力”。
- 页面包含“业务转译”。
- 页面包含微信引流位。
