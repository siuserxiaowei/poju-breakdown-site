# 内容抽取审计

## 数据来源

源目录：

`/Users/siuserxiaowei/Downloads/生财有术AI航海家大会-精华拆解（Day1+Day2）/破局拆解`

当前共 24 个 Markdown 文件，站点中的 24 条 case 与源文件一一对应。源文件大多是“智能总结 + 章节概要”的结构，不是原始逐字稿全文，因此本次数据层采用“正文总结优先、文件标题补足、跨稿件归纳校准”的方式整理。

## 固定字段

每条 case 都包含以下字段：

- `guestIdentity`：嘉宾身份
- `realResult`：真实结果
- `keyData`：关键数据
- `coreStory`：核心故事
- `methodFramework`：方法框架
- `tools`：工具清单
- `quote`：金句
- `valueScore`：钱、关系、技能、影响力，分别含短期和长期评分
- `pillars`：道、法、术、器
- `actionList`：今天、本周、本月
- `xiaoweiView`：小伟视角

## 抽取原则

1. 能从正文明确读到的数据，优先保留具体数字，例如团队人数、营收、订单、用户量、时长、比例。
2. 嘉宾身份优先来自标题、开场介绍和总结段落。
3. 方法框架优先提取成可迁移模型，例如“四步工作流”“AI机会三层”“能力七级”“四类杠杆”等。
4. 工具清单保留具体工具、平台、系统名，也保留“知识库”“Agent”“私域”等资源型工具。
5. 道法术器不是原稿标题字段，而是按用户指定固定套路二次归纳。
6. 小伟视角不是嘉宾原话，是把该主题转译到小伟后续内容/私域/模板业务里的应用角度。

## 信息不足说明

部分交流型稿件没有单一嘉宾或完整商业结果，例如：

- `AI应用与商业创业交流讨论.md`
- `AI电商破局与发展讨论.md`
- `AI破局俱乐部线下大会提问与成员成长分享.md`

这类稿件的数据字段使用“讨论中出现的结果/目标/建议”来承接，不伪造成单一嘉宾案例。

## 后续升级

后续用户再给十几份 Markdown 时，应按同一流程新增：

1. 先生成或追加 `data/cases.json`。
2. 每条 case 至少补齐 7 个抽取字段、4 维评分、道法术器、行动清单、小伟视角。
3. 再运行 `npm run build` 和 `npm run validate`。
4. 发布前人工抽查 3 篇长稿，确认关键数据没有被标题党式误读。
